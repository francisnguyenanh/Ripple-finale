## Login protection: what holds and what does not (SEC-02, 2026-10-30)
`POST /v2/auth/login` counts failed attempts in three layers shared by every instance through the database (`infra/login_protection.py`, tests `tests/security/test_sec02_login_abuse_http_db.py`, `test_sec02_two_process.py`, `tests/unit/test_login_protection.py`): the (account, source) pair locks after 5 failures for 300 s, a source after 100 failures for 300 s, an account from every source after 60 failures for 60 s (privileged accounts 20 / 300 s). What this gives: one source cannot lock an account for other sources; spraying from one source is bounded; distributed guessing of one account is rate-limited; a locked key is answered before the credential check and never grows a counter; account existence is not revealed. **What it does not give (accepted for the public demo):** lockout denial of service is not eliminated: an attacker with at least 12 coordinated sources can re-lock an account for 60 s as soon as each lock expires; people behind one shared address who mistype the same account lock their pair for 5 minutes; a database outage makes sign-in answer 429 until it returns (fail closed); the fixed counting window allows up to twice a limit at a window edge; no CAPTCHA or external service is used; the credential check is not constant-time. The source address depends on the ingress contract `RIPPLE_TRUSTED_PROXY_HOPS`, which is verified on the deployment before traffic (runbook `FINAL_DEPLOY_ROLLBACK.md` section 2), not assumed.

## Prompt rendering and injection (AI-01, 2026-10-30)
Most prompt builders substitute their placeholders one after another (`str.replace`), so a placeholder literal typed by a person (for example `{knowledge}` in a question)
is expanded by a later substitution, and a section-closing tag in a person's text is not neutralised except in the request assistant. What was verified (every enabled
role's builder read; the per-builder table is in the development plan record, not part of the submission): no builder substitutes, after a person's or a source's text, data that the
same reader may not already see (the knowledge pack is filtered by `evidence.read` before it is rendered; memo, specialist and code builders carry the caller's own
pack or files); an oversized expansion fails the asker's own job at the input ceiling (`budget_exceeded`) and nothing else. **What is not claimed:** that model output
cannot be steered by such text — the schema and the validators constrain structure, references and numbers, not meaning; resistance to prompt injection has not been
verified semantically and a single-pass renderer with neutralised delimiters is a deferred change (it alters prompt bytes and would need a replay proof per role).
