# Component guidelines

Implemented shared components. Planned components are not listed until they exist and have a real caller.

| Component | File | Purpose and contract |
|---|---|---|
| `Button` | [button.tsx](../../frontend/src/components/ui/button.tsx) | `variant` primary/secondary/ghost/danger; `size` sm/md/lg (default md); `type` defaults to `button`; `asChild` for links. A disabled action needs a visible reason next to it. |
| `Modal` | [dialog.tsx](../../frontend/src/components/ui/dialog.tsx) | Native `<dialog>` (CSP-safe), `side` center or drawer, restores focus on close. |
| `Tabs*` | [tabs.tsx](../../frontend/src/components/ui/tabs.tsx) | Radix tabs with token styling. |
| `Tip` | [tooltip.tsx](../../frontend/src/components/ui/tooltip.tsx) | Short supplementary label only; never the sole place for a required fact. |
| `Card`, `Muted`, `Callout` | [bits.tsx](../../frontend/src/components/bits.tsx) | Surface with optional `h2` title; secondary text; boxed notice with tone info, warn, danger or wait. |
| `HowItWorks` | [bits.tsx](../../frontend/src/components/bits.tsx) | Routine explanation (walkthroughs, repeated definitions) collapsed under "How this works" (native `details`: keyboard and touch). Never holds a blocker, the consequence of the next action, a paid-use note or a stale / partial warning; those stay visible beside the action. Consumers: Sources update panel (`refresh-how`), Questions knowledge summary (`knowledge-how`), what-if simulation (`sim-how`). |
| `StatePill` | [bits.tsx](../../frontend/src/components/bits.tsx) | Domain state: business label in Business view, raw state in Technical view; `data-state` always carries the machine value. Tone comes from `stateTone` in [stateDisplay.ts](../../frontend/src/lib/stateDisplay.ts); an unknown token is neutral. A label longer than a short status wraps instead of being clipped; pass the full reason as `detail` or as adjacent text. `RUNNING` shows a small decorative dot that pulses only when motion is allowed; the label itself never animates, so its contrast holds in every frame. |
| `StatusBadge` | [StatusBadge.tsx](../../frontend/src/components/StatusBadge.tsx) | Generic loading, empty, queued, running, waiting, stale, partial, failed, success, info or simulated badge: icon plus text. A `success` label should name its scope. |
| `Field`, `TextInput`, `TextArea`, `Select` | [bits.tsx](../../frontend/src/components/bits.tsx) | Labelled controls (`min-h-10`, `bg-bg`). `Select` is the shared native select; give it a visible label through `Field` or an `aria-label`. |
| `Tech`, `TechField`, `Fingerprint`, `Name`, `Path`, `ClaimLabel`, `ClaimTitle` | [bits.tsx](../../frontend/src/components/bits.tsx) | Business and Technical views of the same fact; technical-only content is not rendered in Business view. |
| `Denied` | [bits.tsx](../../frontend/src/components/bits.tsx) | Refused read: plain panel, announces the refusal once, reveals nothing. |

## Decision and evidence presentation (`frontend/src/components/decision/`)
| Component | File | Purpose and contract |
|---|---|---|
| `ResultSummary` | [ResultSummary.tsx](../../frontend/src/components/decision/ResultSummary.tsx) | Titled outcome block: `scopeLabel` says how far the facts reach; `warnings` (`Notice[]`) always render before the content and the action; `availability` `unavailable` shows a notice instead of a guess. Blocking notices use `role="alert"`. |
| `NextActionPanel` | [NextActionPanel.tsx](../../frontend/src/components/decision/NextActionPanel.tsx) | The one next step: visible reason text, optional actor label, `blocked` state, action element supplied by the owning feature (does nothing on mount). |
| `OriginTag`, `OriginSection` | [Origin.tsx](../../frontend/src/components/decision/Origin.tsx) | Where content comes from: `origin` `ai` (dashed border, sparkle icon, "AI"), `source` (document icon) or `engine` (gauge icon); an unknown origin is neutral (`originDisplay` in [originDisplay.ts](../../frontend/src/components/decision/originDisplay.ts), tested in `originDisplay.test.ts`). `OriginSection` keeps the caller's `aria-label`, test id and `data-status`, adds `data-origin`. Origin is not validation: checks and human confirmations keep their own displays. Consumers: assistant answers (model blocks "AI"; the server's authority sentence "Task record"), simulation panel (scenarios, critic and interpretation "AI"; engine table "Engine"). |
| `TrustStateSummary` | [TrustStateSummary.tsx](../../frontend/src/components/decision/TrustStateSummary.tsx) | Independent completion axes side by side, never merged into a score or a green badge. A missing axis reads "Unavailable" (`axisDisplay` in [trustAxes.ts](../../frontend/src/components/decision/trustAxes.ts)). |

Other specialist components (semantic delta, findings triage, provenance inspector, simulation outcome, AI interpretation preview) are added only together with their first real consumer and are documented here when they exist.

## Request tasks (added 2026-10-20, RUX-02..06)
| Item | File | Purpose and contract |
|---|---|---|
| `TaskFrame` | [TaskFrame.tsx](../../frontend/src/features/request-assistant/TaskFrame.tsx) | Feature component with two real consumers (Changes, business change review). Reads `GET /v2/requests/{family}/{id}/task-view` itself (a documented exception to "no fetch on mount": read only, never polled, reloaded when the owning page's data changes). "My task" = Input / What to do (only `obligation_me` current steps) / Result to hand over; eligible-not-asked steps say why; blockers above the action. "Whole request" lists canonical steps with text states, per-step obligations, waits and `parallel_group` peers; `task=map` and `step=<code>` live in the URL and a linked step takes focus. Test ids: `task-frame` (`data-stage`, `data-mode`), `task-my-obligation`, `task-eligible-not-asked`, `task-not-yours`, `task-map-step` (`data-step`, `data-state`, `data-parallel`), `task-map-detail`. |
| `WorkInbox` / `useInbox` | [WorkInbox.tsx](../../frontend/src/features/inbox/WorkInbox.tsx) | My work from `GET /v2/work/inbox` `sections` (mine, optional, blocked, waiting for a person, waiting for the system, recent; legacy lists as fallback). No timer: read again on focus / visibility. A waiting item links to its step on the whole-request view; `unavailable` > 0 is said, never an empty list. Test ids `work-todo` / `work-waiting` / `work-recent` with `data-section`, `data-family`. |
| `RequestAssistant` / `AssistantMessage` | [RequestAssistant.tsx](../../frontend/src/features/request-assistant/RequestAssistant.tsx) | Private panel; keyed by account, workspace, family and request so nothing carries over on a switch; hidden when the feature is off. EUI-02: suggested questions (`suggestQuestions` in [guide.ts](../../frontend/src/features/request-assistant/guide.ts), from the task view only) and the composer show at once, no Start step; "Ask AI" sends that question (one paid call, the note is linked with `aria-describedby`), "Edit question" only fills the composer; the first question uses the idempotent first-ask route and a retry of the same question reuses its key; nothing is created or called on open, edit, hover or poll. "Go to" chips (`actionTarget`, `actionStillCurrent`) focus an existing control of the page for a server action the reader is still asked to do; they never submit; no target = "not available on this page". In TaskFrame the panel sits beside the task from 1280 px (`task-workspace` `data-rail`), below it otherwise, and switching My task / Whole request keeps the draft. `AssistantMessage` is the presentational answer (blocks labelled Fact / Interpretation / Suggestion; Business citations show a readable kind and sentence, Technical shows the fact id and text; next steps = the reader's current actions as text). |
| `useTaskView` / `responsibility` | [taskView.ts](../../frontend/src/features/request-assistant/taskView.ts) | The projection read once per page and shared (Changes: task frame, journey and next step); `responsibility` is who holds the current step for this reader. The journey and the next-step text show "You" only where the projection says the reader is asked now (`alignNext`, unit-tested in `held.test.ts`). |
| `formatEngine` | [simFormat.ts](../../frontend/src/features/questions/simFormat.ts) | Engine numbers: shares as percentages, changes in percentage points, days with unit, "Unavailable" never 0, no rounding beyond the stored value. Tested in `simFormat.test.ts`. |

Catalogue examples (synthetic, no request): the asked approver with parallel later steps, the may-but-not-asked reader, the whole-request view, and answered / historical / withheld assistant messages (`catalog-cat-task`, `catalog-cat-assistant`). These read server projections; they never decide who may act. A new surface that shows request state reuses the task projection instead of deriving stages in the client.

## Rules for these components
- Props carry presentation and callbacks only. No component fetches or mutates on mount.
- Keep `data-testid` and `data-state` stable; tests rely on them.
- Anti-patterns: a second modal implementation, a new status-to-colour map, a custom pill for an instruction-length sentence, a native select styled with an undefined token.

## Adding or changing a component
Update the table above, add a real example in the consuming feature, and extend the unit test that covers the display mapping (see [stateDisplay.test.ts](../../frontend/src/lib/stateDisplay.test.ts)). Deprecations are listed here with the replacement and the remaining callers.

Deprecated: a raw `<select>` with local classes. Replacement: `Select` from `bits.tsx`. Nine raw selects remain (listed as `E03` legacy debt in `frontend/design-system-policy.json`: Analysis and Apply stages, Harbor, Support workspace section, the shell workspace picker; the business change review migrated with EUI-06); migrate each with the package that owns the page, then delete its policy entry. New raw selects are rejected by `npm run check:design`.
